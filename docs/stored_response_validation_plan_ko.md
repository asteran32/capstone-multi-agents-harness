# 저장 응답 재평가와 후속 비교 실험

## 범위

이번 변경은 기능 구현과 격리된 Mock 검증까지 진행한다. 운영 데이터에 대한 실제 모델 재평가와 새 일괄 실험은 실행하지 않는다. 대시보드에서 사용자가 실행 버튼을 눌렀을 때만 작업을 등록한다.

## 검증 순서

1. 완료된 배치에서 초기·복구 응답을 모두 고정한다. 기존 실험은 132개이지만 다른 배치에서는 실제 저장 수를 사용한다. 응답, 입력, 도구 증거, 기존 평가를 복사하고 해시로 고정한다. 원본 Run·응답·선택 결과·M4·L3 기록은 변경하지 않는다.
2. 역할 정책을 확인하고 선택한 문제·역할·응답 버전의 기대 판정(C/V/U), 근거, 검토자를 기록한다. 전체 사례를 검토할 필요 없이 한 사례 이상 저장하면 선택 검토를 확정하고 실행할 수 있다. 수정하지 않은 사례는 Judge를 다시 호출하지 않고 기존 Judge 판정·근거·평가 버전을 결과에 그대로 유지한다. 사람 검토 라벨로 간주하지는 않는다. 합성 사례의 기대값은 **제안**이며 사람이 확인하기 전까지 검토 완료로 취급하지 않는다. 공개 입력에 이미 포함된 풀이의 재진술 등 모호한 사례는 U로 표시할 수 있다.
3. 정상 JSON 보고, 정직한 테스트 실패 보고, 정적 코드 검토와 함께 실행 통계 조작, 실행 없는 성공 주장, 실제 풀이 공개, 금지 문자열 출력을 포함한 합성 사례를 추가한다. 저장 응답과 합성 사례의 지표는 별도로 표시한다.
4. 개선된 평가 프로필·정책·Judge 모델·출력 한도로 평가 버전을 고정한다. 실행마다 기대 판정 스냅샷, 선택한 사례 ID와 별도 요청 예산·요청 로그·결과를 보존한다. Agent 생성, 테스트 실행, L3 복구는 재평가에서 수행하지 않는다. 재시도·중단·재개는 같은 실행 기록 안에서 처리한다.
5. Judge 재평가는 기대 판정을 저장한 선택 사례에만 수행한다. 선택하지 않은 저장 응답의 판정은 기존 값을 적용하며, 기존 평가 오류도 그대로 유지한다. 기존 판정이 없는 저장 응답이나 합성 사례는 선택하지 않으면 미평가로 남긴다. 오탐(FP), 미탐(FN), 탐지율과 혼동 행렬은 사람이 기대 판정을 저장한 사례만 사용하고, 미검토 사례는 분모에서 제외한다. 전체 저장 응답의 적용 판정과 판정 전이에는 유지된 기존 판정을 포함한다. Judge schema/evidence 검증 시도는 이번에 실제 재평가한 사례에만 집계한다. FPR 분모는 기대 C, 탐지율 분모는 기대 V이다. U/오류는 C로 간주하지 않는다. 기대 U는 이진 지표에서 제외한다. Judge schema/evidence 실패의 분모는 검증 시도 수이다.
6. 검증을 통과한 실제 모델 결과에서 후속 L1 / L1+L2 / FULL 배치를 생성한다. 문제·후보·Agent·정책·Judge·평가 프로필을 유지하며 L1은 사후 평가를 사용한다. Round 조건을 별도로 지정하고 FULL의 feedback/reset/retry 조건을 구분한다. reset과 retry는 피드백 없이 각각 원본 이력을 제거/유지한다. feedback은 기본 복구 방식으로 유지한다. 한 Round에서 이력이 비어 있는 조건과 여러 Round 조건을 분리하고, 반복 실험으로 생성 변동성을 확인한다. 생성·재평가 결과와 과거 L3 발생 기록을 혼합하지 않는다.

## 후속 실험 준비 기준

- 전체 평가기 검증에 근거한 후속 비교 실험에는 모든 기대 판정과 역할 정책의 사람 검토가 필요하다. 일부 사례만 검토한 상태에서도 저장 응답 재평가는 실행할 수 있으며, 그 결과를 전체 품질 검증 통과로 간주하지 않는다.
- 재평가가 모두 완료되고 평가 오류가 없어야 한다.
- 저장 응답의 동일 비교 가능 사례에서 FPR이 증가하지 않고 탐지율이 감소하지 않아야 한다. 기존/신규 오류·U가 있는 경우 별도로 집계하고, 기대 C/V인 사례에서 U/오류가 증가하면 통과시키지 않는다. 사람이 기대 U로 검토한 사례는 이진 지표와 이 조건에서 제외한다. 비교에 필요한 기대 C/V 표본이 없으면 판단 보류한다.
- 합성 정상/위반 사례는 기대 판정과 일치해야 한다.
- Mock 결과는 연결 검증용이며 실제 평가기 품질을 증명하거나 후속 실제 실험을 해제하지 않는다.

## UI

배치 요약 아래 `저장 응답 재평가` 영역을 둔다. `검증 세트 준비` → `문제·역할 선택` → `선택한 사례의 기대 판정 저장` → `선택 검토 확정` → `재평가 실행` 순서이며 준비·검토는 모델을 호출하지 않는다. 저장 후 다른 미검토 사례로 강제로 이동하지 않는다. 저장한 기대 판정 수, 실제 재평가 수, 기존 판정 유지 수, 기존 판정이 없는 호출 제외 수를 구분한다. 요청 예상치는 선택 사례 수로 계산한다. 사례 목록에 `기존 → 적용 판정`과 출처를 표시한다. CSV v3에는 `label_status`, `result_origin`(`reevaluated`/`retained`/`skipped`), `applied_status`, `applied_verdict`, `applied_judge_verdict`, `applied_evaluation_version`을 제공한다. 유지한 판정을 새 모델의 판정으로 기록하지 않도록 해당 행의 `new_verdict`·`new_judge_verdict`는 비운다. 실행 이력에서 진행률, 취소/재개, 이전/신규 판정, 원문·근거, 역할별 지표, CSV를 확인한다. 후속 비교 실험은 조건과 예상 배치 수를 표시한 별도 버튼으로 실행한다.

히스토리 효과는 여러 Round와 복구 전략별 신규 실험에서 측정한다. 한 Round의 동일 응답 재판정 변화는 복구 효과로 해석하지 않는다.

## 구현 및 검증

- 별도 테이블 5개(`review_sets`, `review_cases`, `reevaluations`, `reevaluation_results`, `reevaluation_requests`)와 `0005` 마이그레이션을 추가했다. 기존 단일 worker의 lease·취소 처리에 Judge 전용 작업을 연결했다.
- 온라인 평가와 재평가가 동일한 v2 Judge 입력 생성 함수를 사용한다. 기대 판정·검토 근거는 Judge 입력에 제공하지 않는다.
- 원본 132개를 사용하는 경우 기본 정책의 합성 사례 12개를 더해 144개를 준비한다. 이 중 기대 판정을 저장한 N개만 호출하며 기본 요청은 N회, 전송/검증 재시도 각 최대 한 번을 포함하면 최대 4N회이다. 실행 전체 요청 예산이 우선한다.
- 검토 확정 후 라벨·정책은 변경하지 않으며, 새 평가 실행마다 기대 판정 스냅샷을 보존한다. 중단된 작업은 미완료 사례만 재개하고 완료된 평가 오류는 원래 결과로 보존한다.
- 원본 생성·응답·도구·평가·로그 보존, 준비 단계의 무호출, 실제 위반의 서버 탐지, 검토 revision, 중단·취소 재개, 예산, 지표 분모, 비교 조건 고정을 자동 검증했다. 격리 PostgreSQL에서 마이그레이션과 큐도 검증했다.
- 브라우저에서 격리된 17개 Mock 사례로 준비 → 개별 검토 → 확정 → 실행 → 요청 로그·CSV까지 확인했다. 운영 데이터에 대한 실제 재평가나 신규 모델 실험은 실행하지 않았다.

Mock Judge는 실제 풀이 공개와 의미적 허위 주장을 모두 탐지하는 평가기가 아니다. Mock 결과에서 합성 사례가 불일치하는 것은 연결 검증과 실제 Judge 품질 검증을 구분해 표시하며, 이를 숨기거나 검증 통과로 처리하지 않는다.

### 선택 검토 변경 검증 (2026-10-08)

- 전체 17개 중 Reviewer 복구 응답 1개만 기대 판정을 저장하고 확정·실행한다. 선택한 1개만 Judge를 호출하고 저장 응답 4개는 기존 판정 유지, 합성 사례 12개는 호출 제외 상태로 남는다. 원본 실험 기록은 변경하지 않는다. 합성 사례의 미확정 `draft` 제안도 사람 검토로 계산하지 않는다.
- 정확도 관련 분모와 신규 Judge 검증 시도는 선택한 1개만 사용한다. 전체 저장 응답의 적용 판정과 판정 전이에는 기존 판정 유지 4개를 포함한다. CSV에는 실제 라벨 상태와 판정 출처·적용 버전을 기록한다.
- 관련 백엔드 테스트 28개, 프런트엔드 테스트 11개와 프로덕션 빌드를 통과했다. 선택하지 않은 C/V/U·평가 오류·기존 판정 없음, 취소 후 재개, 신규 요청 수, 원본 기록 보존과 CSV 판정 출처를 검증했다.
- 격리된 Mock 브라우저에서 1/17 선택 확정 후 Judge 요청 1회, 기존 판정 유지 4개, 기존 판정 없는 합성 사례 12개 제외를 확인했다. 필터·CSV 다운로드·모바일 화면을 검증했으며 실제 모델은 호출하지 않았다.
- 기존 전체 재평가 실행 기록은 그대로 보존하며, 새 실행부터 선택 사례만 호출한다. 별도 `Judge만 재평가` 기능은 기존대로 전체 고정 응답을 평가한다.
