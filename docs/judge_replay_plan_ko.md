# 고정 Agent 응답의 Judge 재실행

## 승인된 범위

배치 `4b34a2af-ef35-4082-8c13-8c9c67b5225c`의 저장 응답 90개(역할별 30개)를 포함해, 완료된 배치의 응답과 입력·도구 증거를 고정하고 Judge만 반복 실행한다. 합성 사례와 사람 기대 라벨은 요구하지 않는다. Agent 생성, 테스트 실행, L3 복구, 원본 판정·history 변경은 수행하지 않는다.

기존 사람 라벨 기반 재평가는 유지하고 `judge_replay` 모드를 추가한다. 기존 재평가 테이블·작업 큐·요청 로그를 재사용하며, 모드가 없는 과거 기록은 `labeled_validation`으로 해석한다.

## 구현 순서

1. 저장 응답만 포함하는 고정 세트를 준비한다. 초기·복구 응답의 ID·버전·원문·입력 스냅샷과 해시를 보존하며 실제 역할별/버전별 수를 표시한다. 준비는 모델을 호출하지 않는다.
2. 실행 설정 미리보기에서 원본 정책 유지(기본) 또는 현재 `default.yaml`, Judge 모델, 예산을 선택한다. 현재 `judge.yaml`의 평가 프로필을 읽고 설정 해시를 보여준다. 미리보기 이후 파일이 변경되면 다시 확인하게 한다.
3. 새 실행마다 정책·Judge 프로필·모델·예산·평가 버전을 고정한다. 같은 세트를 다시 실행할 때 최신 Judge를 읽되, 이전 실행과 재시도/재개는 저장된 설정을 사용한다. 같은 요청 키는 같은 실행을 반환하며 동일 세트의 동시 실행은 막는다.
4. Judge 판정과 서버 검사를 포함한 종합 판정을 구분해 비교한다. 역할별 C/V/U·오류·미완료, 기준별 전이, 변경 사례, schema/evidence 실패의 분모, 요청·보고된 토큰, 상세 로그와 CSV를 제공한다. 사람 라벨 없는 정확도·오탐률·미탐률은 산출하지 않는다.
5. Mock 테스트로 원본 불변성, 무생성/무도구 호출, 설정 고정, 재시도·취소·재개, CSV·UI와 기존 라벨 기반 검증 흐름을 확인한다. 실제 배치에 대한 유료 Judge 호출은 개발 검증에서 실행하지 않는다.

## 해석과 실행

원본 정책 1.3.0을 유지하면 같은 역할 정책 아래 Judge 변경을 비교한다. 현재 정책 1.4.0을 적용하면 정책과 Judge가 함께 변경된 결과다. 허용된 원본 인용의 범위도 선택한 정책을 따른다. 기존 판정·사람 라벨·감사 의견은 새 Judge 입력에 제공하지 않는다.

고정된 응답의 `uncertainties` 개수와 원본 L3/M4/history는 변하지 않는다. 재판정은 복구 효과나 모델 정확도 개선의 증명이 아니다. 서버의 형식·금지 문자열·저장 도구 증거 검사와 Judge schema/evidence 검증은 로컬에서 다시 수행한다.

배치 화면의 **Judge만 재평가** → **저장 응답 고정** → **실행 설정 확인** → **Judge 실행** 순서로 사용한다. 90개 응답의 기본 호출은 90회, 전송·검증 재시도 각각 최대 2회로 전체 최대 360회이며 실행 예산이 우선한다. 공급자 호출 직후 응답 저장 전에 프로세스가 종료된 경우 중복 요청 가능성은 로그의 `unknown` 상태로 남는다.

## 구현 결과

- `ReviewSetCreate.mode=judge_replay`로 합성 사례 없는 고정 세트를 만든다. 초기·복구 응답을 모두 포함하고 실제 개수와 버전을 보여준다. 기존 기록의 모드 해석과 idempotency 해시는 유지한다.
- `POST /api/review-sets/{id}/replay-preview`는 Judge 모델, `policy_source=original|current`, 요청·토큰 예산을 받아 설정과 해시를 반환한다. 모델 호출과 실행 기록 생성은 없다.
- `POST /api/review-sets/{id}/replay`는 같은 설정과 `expected_config_sha256`, `Idempotency-Key`를 받아 별도 실행을 등록한다. 미리보기 이후 설정이 바뀌면 409로 응답한다. 이미 접수한 키의 재요청은 저장된 실행을 반환한다.
- 새 실행마다 최신 Judge 프로필을 고정하며, 재시도·재개에는 파일을 다시 읽지 않는다. 같은 세트의 실행·재개는 동시에 진행할 수 없다. 요청 한도는 최소 응답 수 이상이어야 하고 재시도도 한도에 포함된다.
- 기존 재평가 조회·상세 로그·취소·재개·CSV API를 재사용한다. CSV 스키마는 3이며 정책·Judge 프로필 해시, 기존/신규 Judge 판정과 기준별 이유·증거를 제공한다. 선택 재평가의 기존 판정 유지와 구분하도록 판정 출처·적용 판정·적용 평가 버전도 포함한다. Judge 전용 실행은 모든 응답을 재평가하며, 기대 판정·검토자·검토 근거는 비운다.
- Judge 의미 판정과 서버 검사를 포함한 종합 판정을 별도로 집계한다. 실패 시 내부적으로 저장하는 U 대체값은 유효한 Judge 판정으로 표시하지 않으며 `평가 오류`로 집계한다. 기준 체계가 다른 과거 판정은 `legacy:`로 구분하고 없는 대응 기준은 `해당 없음`으로 표시한다.
- 기존·신규 판정이 각각 C/V/U 중 하나인 사례만 판정 변경 비교에 포함한다. 평가 오류·미완료는 별도 항목이다. 사용량은 공급자가 보고한 토큰의 합이며, 미보고 요청 수를 함께 표시한다. 사람 라벨 기반 정확도 지표나 후속 비교 실험 검증 통과 자격은 부여하지 않는다.
- `JudgeReplayPanel`을 배치 요약 아래 추가하고 기존 `ReevaluationPanel`에서는 사람 라벨 기반 세트만 표시한다. DB 테이블 추가나 마이그레이션은 필요하지 않다.

## 검증 결과

2026-10-08, 운영 DB 및 실제 LLM 호출 없이 검증했다.

- 관련 백엔드 테스트 67개 통과: 신규 Judge 전용 실행, 기존 재평가, Judge 설정 고정, v3 평가, CSV, few-shot 계약. 오류 표시 보완 후 영향 범위 25개를 재실행하여 통과했다.
- 프런트엔드 테스트 11개 통과 및 TypeScript·Vite 빌드 성공.
- 격리 SQLite의 30문제 × 3역할 Mock 실험에서 응답 90개를 고정하고 Judge 요청 90회만 발생함을 확인했다. 원본 Batch·Run·Call·Response·Snapshot·Evaluation·ModelRequest·ToolExecution·Log 지문과 배치 집계를 실행 전후 대조했다.
- 기대 라벨 없는 실행, 합성 사례 제외, 미리보기 무호출, 정책 선택, 파일 변경 감지, 실행별 버전 고정, 중복 요청, 취소·재개, 증거 검증 재시도, 예산 오류, 해시 변조 중단, CSV를 자동 검증했다.
- 임시 DB·Mock 모델의 실제 브라우저에서 90건 재평가를 두 번 실행하고 기존 기록 선택, 역할·판정 변경 필터, Judge 로그, CSV 다운로드를 확인했다. 데스크톱과 390px 모바일에서 JavaScript 오류와 페이지 가로 넘침이 없었다.
- 실제 배치 `4b34a2af`의 Judge 재평가는 수행하지 않았다. 기능 검증 결과는 실제 모델의 판정 정확도 개선을 의미하지 않는다.
